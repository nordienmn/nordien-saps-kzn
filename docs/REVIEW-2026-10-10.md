# SAPS KZN demo: full review

Reviewed 2026-10-10 by Claude. Branch `review/claude-2026-10-10`. Nothing on `main` or on the live service was changed.

**Evidence labels used throughout**

- **[LIVE]**: observed on the public Cloud Run site with read-only requests, no forms submitted, no desk login.
- **[LOCAL]**: reproduced on a local copy of the repo. I checked that all seven live pages are byte-for-byte identical to the repo, so every [LOCAL] page or behaviour finding also applies live. The one exception is path traversal (finding 6), which the live front end blocks.
- **[CODE]**: read in the source and not exercised in a browser.
- **[RESEARCH]**: from a web search made during this review. Sources are listed at the end.
- **[MEMORY]**: from my general knowledge and not looked up in this session.

**Limits of this review**

- The browser pane blocks the microphone, camera and location, so a real call, a real camera photo and a real GPS fix were never tested. The profile photo was injected through browser storage.
- I did not use the live desk password and did not submit anything to the live site.
- Kimi's review has not been received yet. Nothing here relies on it.

## 1. Verdict in one paragraph

The demo tells a good story on the happy path: a citizen taps Emergency, a file appears at the desk, a tip can be escalated, and the commissioner board flashes. But it is a prototype that looks and behaves like one. Three things matter most before senior management sees it:

1. **Several promises on screen are not true.** The call operator says "I can see your location" when no location was sent. The call log says "Recording … on the file" when nothing is recorded. Mute and Speaker only change their labels. The profile photo never reaches the desk.
2. **A public, unauthenticated page carries the SAPS badge and "Call 10111".** Anyone on the internet can read every record and rewrite any of them, and one stored-XSS bug runs script on the desk and board.
3. **The design is not at the standard of our other apps.** There is no design system. Seven pages carry seven slightly different looks, and there are no icons, no motion and no map (details in section 5).

## 3. Functional findings (ranked)

### Critical

1. **Anyone can rewrite any case.** `POST /api/route/<id>` has no authentication. An anonymous call changed a seeded case's desk, status and officer and appended "Verified by head office." It also returns "ok" for IDs that do not exist. [LOCAL]
2. **Anyone can read every record**, including named seed data, at `GET /api/reports`. [LIVE] [LOCAL]
3. **Stored XSS on the desk, commissioner board and brief.** Fields are inserted into the page unescaped. A tip with a script payload ran on all three pages (tab title changed). On the desk it fires the moment an operator opens the Anonymous door. [LOCAL]
4. **The desk password is checked only in the browser, and pre-filled.** Opening the page source gives it away. The commissioner board, `/brief` and `/municipality` need no login at all. [CODE] [LOCAL]
5. **The call claims abilities it does not have.** "I can see your location" is spoken with an empty address. "Recording and transcript are on the file" is logged though no recording code exists. [LOCAL]
6. **Path traversal in the static handler**: `/static/../server.py` returned the server source locally. Live returns a redirect (blocked by Google's front end), but the handler remains vulnerable on any other host. [LOCAL] [LIVE]

### High

7. GBV request has no callback number and no location, so "Call you now: Yes" cannot be honoured. [LOCAL]
8. Every submission defaults to cluster "Durban Central", so the board's cluster map and brief are skewed. In my run, 8 of 12 records sat in Durban Central. [LOCAL]
9. The citizen never sees the confirmation (off-screen), and the form can be double-sent. [LOCAL]
10. A referred tip flashes below the fold, so the red flash is invisible at normal screen heights. [LOCAL]
11. The desk shows no call state (ringing, live, ended), no log, no mobile, no address detail, no time or age, no sound, and has no action on Calls or Crime doors. [CODE] [LOCAL]
12. Refreshing the desk drops the login; first open shows an empty door for about two seconds (data not yet loaded). [LOCAL]
13. The weather SOS fires on a single tap and then reveals itself. [LOCAL]
14. The public demo can be mistaken for a real emergency channel. Calls are labelled "SAPS KZN desk. Not the national 10111 centre" only in a note the citizen never sees. [CODE]

### Medium

15. isiZulu covers perhaps a third of the screens (finding in test 2). [LOCAL]
16. Crime form defaults to "Armed robbery"; choosing "Domestic violence" sends it to the Crime door rather than GBV. [LOCAL]
17. Dropped pin is a random coordinate in a KZN box (not where the person put anything), and there is no map. [CODE] [LOCAL]
18. Board filters: "stations" and "areas" are the same list; "crime types" mixes labels like "Voice call", "Park", "GBV SOS"; "places" lists raw addresses and coordinates. KPI "Open" equals "Received" because nothing can close a case. [LOCAL]
19. `/brief`: "Today" and "This week" both show the total count; "tips not acted on" counts every unverified tip; it lists every citizen's name. [LOCAL]
20. `/flying`, `/umlazi`, etc. are empty forever. Nothing in the UI can send a case there. [LOCAL] [CODE]
21. Server basics: no size limit, no validation, malformed JSON drops the connection, `SEQ` counter not locked, case numbers hard-code `/10/2026`, cp1252 default breaks `python server.py` on Windows, container runs as root, no security headers. [CODE] [LOCAL]
22. Data is in memory with one instance. A restart wipes it. [CODE]

## 5. Design review: why it looks amateur

Measured against the Nordien design DNA (restrained neutral base, one confident accent, tokens in CSS variables, per-product identity) and our UI/UX research:

- **No design system.** Only 1 of 7 pages defines `:root` tokens. Each page hard-codes its own colours. Pages use three different looks: citizen is dark navy with a gold pill; desk and commissioner are near-black; `/brief`, `/municipality` and `/weather` copy iOS grey; `portal.html` uses a different font again. A senior viewer clicking through will feel six apps.
- **System fonts only, no type scale.** Nothing sets the product apart. Our other apps have a deliberate type voice.
- **No icons.** Zero SVGs and zero icon references in the citizen app. The Emergency door, call controls and every tile are text only. Other apps use a consistent icon set.
- **No motion or state design.** 0 transitions across all pages. Panels pop. There are no loading, empty, success or error states worth the name. "Nothing in this door." is the entire empty state.
- **No map.** The commissioner "cluster map" is a hand-drawn polygon with hard-coded dots that overlap (Pinetown, Chatsworth and Durban Central stack on each other). Senior leadership expects a real map.
- **Hierarchy.** The desk list is flat text in dark cards: case, label, name, note. There is no priority colour, age, status chip, or primary action. An operator cannot tell which case needs them first.
- **Citizen flow.** Home screen is fine in structure (Emergency first, large tiles), but the call screen is a black rectangle with a broken image, and confirmations are off-screen.
- **Responsive.** Desk and board have a single breakpoint at most. The desk did not overflow at 1024px; I did not review it at phone width.

**Honest read:** the structure and the product thinking are good. The craft is missing. It reads as a rapid wireframe in colour, not a finished product. It needs a design-system pass and a rebuild of the visible surfaces, not a polish.

## 6. Global comparison

Reference set from the brief. What I could verify [RESEARCH]:

| Reference | What they do | What SAPS KZN has | Gap |
|---|---|---|---|
| **Dubai Police "Police Eye"** | Confidential report with photo, video or voice attachment and a **pinned location**; 9 categories; anonymous option; app in 6 languages | Text report, no working attachments, random pin, 2 languages (partial) | Attachments that actually upload; a real pin on a map; more complete translation |
| **Abu Dhabi "Aman"** | Confidential tip line with 6 categories; **multiple channels**: phone, SMS, app, web, email; guaranteed anonymity; call centre is explicitly "for information, not police reports" | Anonymous tip form only | Channel clarity and an honest promise of what anonymous means; a clear "tip vs report" split (SAPS has this idea, but the page says little) |
| **Tokyo "Digi Police"** | **One-tap alert screen** that turns red and plays a voice message; can notify a designated email; map of crime-prone areas and police stations | Emergency button, no friend/contact alert; no safety map | A "tell someone I trust" step; a nearby-station map; a visible state change when help is requested |
| **China 110 (WeChat mini-programs, e.g. Zhejiang, Yantai)** | Quick-alarm button; **text, photo and video sent discreetly**; one-tap "upload location"; video alarm; fraud-quick-report section | Call and video call exist but are simulated; no discreet text channel | Silent/text alert for someone who cannot speak (the demo script even says "I cannot speak freely"); location upload step |

I could not find Beijing-specific app details in the search, so Beijing 110 is represented by the provincial mini-programs above. Treat that row as indicative.

**Safe-by-design GBV guidance [RESEARCH + MEMORY]:** survivor-safety guidance (for example NNEDV's technology-safety team) stresses that an app can itself put someone at risk. Common patterns: a disguised icon or neutral cover, quick exit, a safe-contact preference ("may we phone you? is it safe to leave a voicemail?"), and sending location only to chosen contacts or services. The SAPS weather door follows the cover idea but fails on quick exit and one-tap confirmation, and the URL and permission prompt expose the `saps-kzn` name.

**South Africa context [RESEARCH]:** the national GBV Command Centre runs a 24-hour line at **0800 428 428**, a "Please Call Me" USSD at **\*120\*7867#**, and an SMS line **31531** for people with disabilities. SAPS KZN GBV flow should show these as the real fallback. (I did not verify the SAPS 10111 centre's own channels beyond the 10111 number itself.)

**Standards [MEMORY, not looked up this session]:** WCAG 2.2 AA (target size, focus, labels, status messages), POPIA notice and purpose rules, and NG911/NENA-style requirements for emergency location and text-to-emergency. Treat these as direction, not citations. Verify before quoting them to the client.

## 8. Recommendations (all buildable on the current Cloud Run service, no new GCP project)

### Before anyone senior sees it (day-one fixes)

1. **Put a visible "DEMO · not a real police service" banner on every page and the call screen**, and a plain line on the citizen app: "This demo does not reach 10111. In an emergency call 10111." Remove or mask the public live URL if the demo is not being shown.
2. **Stop the false claims.** Operator says "I can see your location" only when a location was sent. Log "Recording" only if recording exists. Show real Mute and Speaker behaviour or remove the buttons.
3. **Escape every field** that goes into a page (desk, board, brief, portal pages, municipality).
4. **Protect the write routes**: a shared demo token in a header on `/api/route` and a rate limit on `/api/reports`. Fix the traversal in `/static`.
5. **Fix `face.jpg`** (add the file or remove the dependency) and **send the profile photo** to the desk as part of the case.
6. **Make confirmations visible**: a full-width confirmation that stays on screen with the case number, and clear the form.
7. **Put the red flash where it can be seen**: a pinned "Escalated" strip at the top of the board.
8. **GBV form carries the callback number and location** (from profile or typed), plus a safe-contact choice ("OK to call / SMS only / do not contact").
9. **Weather door**: require a hold or a two-step confirm, add a quick exit that returns to a neutral screen, and hide the panel afterwards.

### Rebuild of the visible surfaces (one design system, applied to every page)

10. **A single design system** with tokens (SAPS navy and gold plus one signal colour), one type scale, an SVG icon set, 4 / 8 spacing, shared components. All seven pages inherit it. Keep SAPS identity distinct from the other Nordien apps.
11. **Citizen**: Emergency as one unmistakable hero; real call states (Calling → Connected → Ended); location chip showing what will be shared; attachments that upload; progress and success screens; full isiZulu including options and messages; `lang` switching; accessible notice dialog.
12. **Desk**: one queue with priority, age, status chips and a primary action per card (Accept, Refer, Escalate, Close); a call card with live timer and state; a case file view with photo, name, mobile, location on a map, log and transcript; sound and visual alert for new items; door badges.
13. **Commissioner board**: a real map with markers (Leaflet/OpenStreetMap), honest KPIs (open vs closed), a cleaned-up filter set, a pinned escalations strip, reduced-motion safe.
14. **A reset route** (token-protected) so the demo can be restored to seed before each showing.

### Later, for production (not for the demo)

15. Server-side auth with roles, a database, audit trail, real telephony (WebRTC or SIP), retention rules, a POPIA notice that records consent, and a security review.
